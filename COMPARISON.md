## What the actual experiment establishes

Invoice's oracle passes every original fixture, including zero values, maximum-safe total, duplicate IDs, mixed currency, negative/fractional/unsafe values and overflow. Independent verification binds the submitted operations and dependency lineage to actual n8n node executions; a compilable literal-answer candidate fails despite successful n8n execution. Invalid YAML/operations fail before n8n. Nop is a known rejection with native reward zero.

Checkout uses the unchanged pinned AutoWFBench source `970bbc8645c4d503d35cb5df05363fb9de132519`, including its stateful checkout source, constrained patch tool, before/after tests, independent final checks, tool-call limits and original scorecard. The reference is not replaced by a mock world. Both the Script reference and the additional Gantt workflow with two LLM operations execute in real n8n and achieve 0.732 under the original **simulated** calibration. Historical saved task contract, run log and judge response replay to the exact original evaluation. This is calibration/interface evidence, not a model-quality measurement.

A runtime timeout or malformed/model-mismatched wrapper response latches the run and prevents another model dispatch. A hard-killed Docker simulator preserves its durable start observation and produces an unknown outcome without retries or a fabricated score. A missing judge leaves semantic quality null even when deterministic acceptance succeeds. Harbor reports the absent reward as `RewardFileNotFoundError`; its aggregate mean is not an appropriate substitute for these nullable research facts.

The public author image's full ancestry and running task boundary are inspected, not merely its final Dockerfile. Real Docker inspection verifies no original checkout mounts, no Docker socket, no privileged containers, no public ports, isolated agent networking, an internal verifier network and a read-only credential mount in verifier main. A non-oracle test agent verifies private paths/credentials are absent and the protected submission directory is unwritable. The simulator's tool token cannot call preparation/finalization endpoints or another world's tools. Native teardown removes the experiment's containers, networks and credential volumes.

The supplied automated tests and `reports/` logs are the evidence of record. Raw native jobs are retained locally under `jobs/`; compact result summaries allow review without committing generated workflows or large engine logs. No result from a fake transport is evidence of real-world Codex reasoning quality.

## Concurrent F1/F2 work

There was no assumption that either fix was present and no wait for ongoing work. At the pinned revision, `coordinate/benchmark_worker.py:admit` exposes a compilation-only admission path, and `main` selects it before its execute/evaluate path. Its normal path also calls world `prepare` before plan construction. `evaluate/records.py:validate_result` checks normalized field types/ranges; the worker projects `harbor_reward` or acceptance directly. The checkout-owned scorer already contains exact Decimal normalization. These are source observations, not claims about a later F1/F2 branch state.

The spike has explicit task entrypoints: invoice compiles all original fixtures before any execution, then actually evaluates them; checkout compiles/admit-checks before preparing its semantic world window. Execution, terminal completion, acceptance, and quality remain different facts. Reward projection rejects inconsistent types, unknown numeric scores, and mismatched checkout totals/normalized rewards. Tests cover these behaviors independently of any later original fix.

Differences attributable to revisions **after** the recorded SHA are **NOT VERIFIED** because this experiment deliberately did not resynchronize. A subsequent comparison must identify a second explicit revision; it must not silently move this baseline.

Remaining custom infrastructure is concrete: one BaseAgent adapter, one bounded submission collector, explicit shared image builds, pinned dependency acquisition/verification, source/model identity records, and the tiny verifier/replay boundary. None is supplied by native Harbor.

Adding another multi-service benchmark means adding one native task directory: public instructions/catalog, an environment Dockerfile, a separate verifier Dockerfile/Compose file, a reference solution and a domain-specific verifier entrypoint. Reuse compiler/runtime via the explicit shared private image. Define its world credentials, limits, tool receipt semantics and independent scoring locally. No registry, descriptor parser or materializer changes are required. The new world's actual correctness, isolation and failure controls still need tests; this experiment does not automate them away.

## Decision and deletion boundaries

**Recommend A: migrate the existing repository toward native Harbor tasks**, retaining its proven domain and research safety mechanisms. The evidence supports replacing the custom benchmark format and task packaging for these two scenarios; it does not support replacing the whole original research system with this spike.

| Question | Answer supported by the experiment |
| --- | --- |
| Can native tasks replace the custom benchmark format? | **Yes for both tested scenarios.** Committed task directories express the public/solution/private closure and native Compose verifier topology. |
| Can `scenario.json`, loader and materializer be removed? | **Yes after migrating their consumers.** No equivalent machinery exists in the spike, and both task types execute through native Harbor. |
| Does Harbor support complex environments? | **Yes for this exact multi-service stateful world.** Health-checked services, internal networks, scoped volumes, separate verifier, native transfer and teardown were exercised. Arbitrary cloud providers/topologies are **NOT VERIFIED**. |
| Which custom components remain necessary? | YAML semantics/compiler, native n8n extraction, independent business checks/scoring, world tool/security/deadline/receipt behavior, Codex transport, model-call budgets, source/prompt/model identity, immutable research evidence and nullable evaluation facts. |
| Are custom experiment/results systems duplicative? | **Partly.** Trial lifecycle/status, artifact transport, scheduling and viewing duplicate Harbor. Cross-job research budgets, experimental admission gates, provenance and historical analysis do not. |
| Adopt the spike as the replacement? | **No.** It intentionally omits lifecycle/repair experiments, paid-operation gates and historical consumers. Move the tested structural simplifications into the maintained repository instead. |

Deletion candidates after corresponding native call-site migration are `scenario.json`, `benchmark.py`, `benchmark_loading.py`, `benchmark_manifest.py`, `harbor_integration/tasks.py`, `coordinate/benchmark_discovery.py`, `benchmark_packages.py`, `packages.py`, and generic `benchmark_worker.py` dispatch. `coordinate/backend.py` can be replaced by direct compiler/n8n calls for this single engine. Generic trial-only responsibilities in `coordinate/runs.py`, `harbor_integration/runner.py` and custom viewers can then shrink around native Harbor.

These are replacement targets, **not safe immediate deletions from the untouched original tree**: existing CLI, tests, historical readers and experiment policies still import them. `coordinate/ledger.py`, live wrapper identity/source inspection, paid-work gating and lifecycle/repair controllers must not be deleted based on this experiment. Keep the proven independent evaluator and security mechanisms even if their placement changes. The original task materializer's security tests should become checks of committed contexts and actual image ancestry.

Migration risks are the missing-reward/exception representation, shared-image caching, public/private context drift, host wrapper tool access outside native containers, provenance compatibility, and accidentally discarding series budgets or historical score semantics when removing generic coordination. The experiment disables paid dispatch; private wrapper source inspection and live judge transport remain **NOT VERIFIED**, so activating paid work requires preserving and revalidating the original gates. The code-size reduction includes omitted capabilities and must not be presented as a production rewrite saving.

Native Harbor removes the need for a second benchmark format and trial framework here. It does not remove the need for a trustworthy workflow runtime and research evaluator.
